Checking the archive host…

Open the archive host

That is a home machine on a free tunnel, so two things follow. It is up when it is up — if it is offline, come back later. And its address changes every time the tunnel restarts, which is why the link above points at a redirector that always knows the current one. Link to https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/… and your link keeps working; link to the trycloudflare.com address it lands on and it will be dead by next week.

What is there

/go/manifest.jsoncounts, sizes, date range
/go/weeks.jsonper week: ids, recordings held, bytes
/go/replay/<uuid>one recording, .ndjson.gz, resumable
/go/week/<week>/replays.jsonwhat that week holds
/go/week/<week>/replays.tarevery recording for that week, streamed as one tar
/go/eu/<match_id>.jsonone tagpro.eu record: match, players, events, splats, ranked skill
/go/eu/week/<week>.json.gzevery tagpro.eu record for that week
/go/bulk/ranked_matches_bulk.json.gzthe whole tagpro.eu export in one file

Weeks are the Monday, UTC — the same keys as the Coverage tables, so a week here holds exactly the matches that week's row counts.

Fetching it with a script

curl -LOJ https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/replay/<uuid>

curl -L https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/week/2026-08-24/replays.tar | tar x

curl -L -C - -O https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/bulk/ranked_matches_bulk.json.gz

-L follows the redirect to wherever the host currently is, so a script written once survives every rotation. -J takes the filename from the server rather than from the url, and -C - resumes a part-finished file. If the host is offline the redirector answers 503 rather than sending you somewhere dead. It is one home uplink: eight transfers run at once and the rest wait, so pull a week at a time rather than opening fifty connections.
