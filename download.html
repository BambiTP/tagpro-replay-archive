Download selection

The link changes as you tick things, and it is the whole request — paste it into a terminal, a script, or a message. This page’s own address tracks your picks too, so bookmarking or sending it hands over the same selection.

Every match carries its uuid and every player their name, whatever else you untick. Recordings are the heavy part — the whole archive is 3.93 GB of them, against roughly 66 MB for every match result ever. Sizes are exact for recordings and an estimate for the rest, since those are built as they are sent.

By week

The same thing a week at a time. replays.tar is that week's recordings, results is how every match ended with per-player stats, and tagpro.eu is that week's mirror records in bulk shape.

Weeks are the Monday, UTC, matching the Coverage tables. results carries the map and its tagpro.eu map id by default — drop it with ?map=0 — and includes rebuilt records marked as such, which ?rebuilt=0 removes.

Ids, timings and held-flags for every match. Small enough to sit on this site, so these links always work, host up or down.

all.replay.json every match: uuid plus the game_id a recording is requested by
missing_replays.json the 113,379 matches with no recording held — the wanted list
all.eu.json every linked tagpro.eu match id (121,669 of them)
coverage.json the per-week totals behind the tables on the Coverage tab
DATA_MAP.md what every field means

Per-week equivalents are linked from every row of the Coverage tables.

Fetching it with a script

curl -LOJ https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/replay/<uuid>

curl -L https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/week/2026-08-24/replays.tar | tar x

curl -L -C - -O https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/bulk/ranked_matches_bulk.json.gz

curl -L -o results-2026-08-24.json.gz \
  "https://tagpro-archive-tunnel.bambitagpro.workers.dev/go/week/2026-08-24/results.json.gz?map=0"

-L follows the redirect to wherever the host currently is, so a script written once survives every rotation. -J takes the filename from the server rather than from the url, and -C - resumes a part-finished file. If the host is offline the redirector answers 503 rather than sending you somewhere dead. It is one home uplink: eight transfers run at once and the rest wait.
