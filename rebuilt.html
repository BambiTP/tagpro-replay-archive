Records rebuilt from recordings

tagpro.eu carries 121,636 of the 123,909 matches here, about 98%. For some of the rest there is a recording in this archive, and a recording contains everything a match record holds. 292 records have been reconstructed that way. They are the orange band on the coverage table.

They are kept separate on purpose. A record derived from a recording is not a tagpro.eu record, so it carries source: "replay" and a synthetic match id from 1,000,000,000 up, well clear of tagpro.eu's id space. Downloads leave them out unless you ask for them — add ?rebuilt=1.

Player rows exact on all seven 1,990 / 1,992 — 99.90%

hold comes out frame-accurate: median error zero, every row within one second. prevent is second-resolution only, because the recording carries it as a counter ticking once a second rather than as events.

Two things the extractor has to get right, and did not at first. Counters belong to a player, not to a slot: a player who rejoins gets a new slot that inherits their accumulated counters, and treating that as a fresh player double-counts everything they had already done. And the units differ — a recording counts hold and prevent in seconds while tagpro.eu stores 60 fps frames — so everything is normalised to frames before it is written.

What a recording cannot supply

These fields are null on a rebuilt record rather than guessed:

  • The packed per-player events string and the per-team splats blob. tagpro.eu's own encoding of these is not reproduced. The events are supplied instead as events_decoded, one object per event.
  • auth, flair, degree, score and points — account and scoring metadata the mirror adds, which is not in the recording.
  • port and timeLimit.
  • mapId is filled in only when the map name matches a map tagpro.eu already knows. No map rows are invented: a recording's map identifier is a different id space, and a fabricated id would corrupt every per-map aggregate downstream.

Where they are better

The event stream from a recording is richer than the mirror's. Every event carries a position. tagpro.eu only has coordinates for pops and drops, and only inside a packed blob that had to be reverse-engineered to read at all.

Getting them, or not

Every tagpro.eu download takes the flag. Without it you get the mirror's records only, which is what tagpro.eu itself would give you:

…/eu/week/2026-08-24.json.gz              mirror records only
…/eu/week/2026-08-24.json.gz?rebuilt=1   with the rebuilt ones mixed in

Both are in tagpro.eu's own bulk shape: an object keyed by match id. See Download.
